> Standing up a repo for a **NEW customer**? Start at
> [NEW_ADOPTER.md](NEW_ADOPTER.md) — the ordered checklist that generates and
> wires the repo. THIS walkthrough assumes the repo already exists and teaches
> you to author tables in it.

This walkthrough takes a brand-new domain (`finance`) from empty folder to a
deployed, quality-gated medallion pipeline **without touching the framework
and without asking the framework team**. Every step names the file you create
and the command that proves it works.

## 0. One-time machine setup

Prereqs: [uv](https://docs.astral.sh/uv/), Java 17+ (local Spark for tests),
Databricks CLI ≥ v0.294.0.

```bash
make lock install       # resolve deps into .venv (`make install` alone is enough
                        # once uv.lock is committed; a freshly generated adopter
                        # repo has none yet, so lock first)
make enable-githooks    # protected-files pre-commit guard
make lint test          # prove the toolchain works before you write anything
databricks auth login --host <your-workspace-url> --profile <cli-profile>
```

Optional: let the agent query your workspace's UC tables read-only while you
author (Databricks MCP, opt-in) — see [AGENT_MCP.md](AGENT_MCP.md).

## 1. The mental model (60 seconds)

- A **target table = one YAML artifact** at `config/<catalog>/<schema>/<table>.yml`
  — the path mirrors the UC namespace ([NAMING.md](NAMING.md)).
  You describe *what* (source, columns + types, quality rules, target kind);
  the framework (an installed dependency) generates all the Lakeflow SDP wiring.
- **Python is only for logic a mapping can't express** — pure functions
  registered with `@transform`, living in your domain package, never in the
  framework.
- **Quality is declarative** (databrickslabs/dqx): `criticality: error` rows
  are dropped into an auto-created `<table>_quarantine` with evidence;
  `warn` rows pass through flagged.
- **Nothing is hardcoded**: catalogs/schemas/paths are conf KEYS resolved per
  environment by bundle variables — promotion never edits your configs.
- Anything that is *not* a managed medallion table (exports, API pulls,
  human-gated triage) is an **edge job**, not a pipeline — see step 8.

## 2. Create the domain skeleton

(A repo generated by the adopter scaffold ALREADY has this skeleton with one
starter bronze table — skip to step 3 there. This step is for adding a domain
by hand.) Copy the example's shape — these folders sit at the repo root (only
the multi-domain template repo nests them under `projects/<catalog>/`).
`finance` is the domain's BASE CATALOG name — folder names carry it
everywhere ([NAMING.md](NAMING.md)):

```
config/finance/domain.yml
config/finance/bronze/  silver/  gold/
src/finance_etl/__init__.py
src/finance_etl/transformations/pipeline.py     # copy VERBATIM from the example
src/finance_etl/transforms/__init__.py
src/finance_etl/checks/__init__.py
```

`config/finance/domain.yml` — the only place your domain names its layers:

```yaml
# yaml-language-server: $schema=<relative path to>/schemas/domain_config.schema.json
schema_version: 1
domain: finance
imports: []                      # add python modules as you create them
catalog_conf: datalab.catalog    # conf KEYS, never literal names
layers:
  bronze: {schema_conf: datalab.bronze_schema}
  silver: {schema_conf: datalab.silver_schema}
  gold:   {schema_conf: datalab.gold_schema}
```

`src/finance_etl/transformations/pipeline.py` is 3 lines and never grows — copy
it verbatim from the `bootstrap-adopter-repo` skill's
[`references/templates.md`](../.agents/skills/bootstrap-adopter-repo/references/templates.md)
(in the template repo, the live copy is
`projects/customer_sales/src/customer_sales_etl/transformations/pipeline.py`).

## 3. Author your first artifacts

**Bronze — incremental file ingest (Auto Loader):**
`config/finance/bronze/invoices_raw.yml`

```yaml
schema_version: 1
name: invoices_raw
comment: Raw invoice feed from the landing volume.
source:
  kind: cloud_files
  path_conf: datalab.finance_landing_path
  format: json
  options:
    cloudFiles.inferColumnTypes: "true"
    cloudFiles.schemaEvolutionMode: addNewColumns
  add_lineage: true              # adds _ingest_ts + _source_file
target:
  kind: streaming_table
```

**Silver — validated, deduplicated, SCD1:**
`config/finance/silver/invoices.yml`

```yaml
schema_version: 1
name: invoices
comment: Current invoice state per invoice_id, validated.
source:
  kind: table
  name: invoices_raw
  layer: bronze                  # resolves via domain.yml — no schema names
  as_stream: true
columns:
  - name: invoice_id
    type: string
    quality:
      - criticality: error       # rows without an id are quarantined
        check: {function: is_not_null}
  - name: amount
    type: decimal(12,2)          # ANSI-safe cast: malformed → NULL
    quality:
      - criticality: warn
        check: {function: is_in_range, arguments: {min_limit: 0}}
  - name: _ingest_ts
    type: timestamp
target:
  kind: streaming_table
  cdc: {keys: [invoice_id], sequence_by: _ingest_ts, scd_type: 1}
```

**Gold — batch aggregate:** `config/finance/gold/revenue_by_month.yml`

```yaml
schema_version: 1
name: revenue_by_month
comment: Monthly invoiced revenue.
source: {kind: table, name: invoices, layer: silver}
transform:
  - function: finance.summarize_revenue
target:
  kind: materialized_view
```

Every field, every source kind (files/kafka/fan-in `sources:`), backfills,
snapshot CDC and sinks: [FRAMEWORK.md](https://github.com/dediggibyte/datalab-framework/blob/v1.0.0/docs/FRAMEWORK.md).

## 4. Add python only where a mapping can't express it

`src/finance_etl/transforms/finance.py`:

```python
from pyspark.sql import DataFrame
from pyspark.sql import functions as F

from datalab.framework.registry import transform


@transform("finance.summarize_revenue")
def summarize_revenue(df: DataFrame) -> DataFrame:
    return df.groupBy(F.date_trunc("month", "invoice_date").alias("month")).agg(
        F.sum("amount").alias("revenue")
    )
```

Then declare it in `domain.yml`: `imports: [finance_etl.transforms.finance]`
— and add a unit test next to your domain (the template repo's
`projects/customer_sales/tests/test_customers_transforms.py` is the shape to
copy).

## 5. Validate before any deploy

```bash
make validate-configs    # pydantic shape + dqx rule validation, exact file+field on failure
make lint test           # ruff + pytest (local Spark)
```

Run a single dataset through the REAL framework path — no workspace needed —
in a test (the template repo's
`projects/customer_sales/tests/test_run_dataset_contract.py` is the pattern), a
notebook/REPL, or against a live cluster via `make validate-connect`:

```python
from datalab.framework import run_dataset
res = run_dataset(spark, "config/finance", "silver", "invoices",
                  params={...}, inputs={"cat.bronze.invoices_raw": sample_df})
res.valid_df.show(); res.quarantine_df.show()
```

`datalab.framework.capture_graph(spark, "config/finance")` prints every
dataset/flow the config will generate, locally.

## 6. Wire the bundle

(A generated adopter repo is ALREADY wired — its `resources/` hold the pipeline
and refresh job for its one domain. Skip to the `make validate` below unless you
are adding a domain by hand.)

1. Start from the pipeline resource in the `bootstrap-adopter-repo` skill's
   [`references/templates.md`](../.agents/skills/bootstrap-adopter-repo/references/templates.md)
   (in the template repo, the live copy is
   `projects/customer_sales/resources/customer_sales_etl.pipeline.yml`) →
   `resources/finance_etl.pipeline.yml`; rename the resource key and `name`,
   point `root_path`/`libraries` at `src/finance_etl`, and set
   `datalab.config_dir: ${workspace.file_path}/config/finance`. Keep
   `serverless: true`; leave `environment_version` **commented out** on a
   brand-new pipeline (Databricks' fingerprint gate leaves it unable to run —
   [ADOPTING.md](ADOPTING.md#first-deploy-traps-found-the-hard-way)). In
   `environment.dependencies` keep `${var.datalab_wheel}` (the framework wheel
   from your catalog's `artifacts.wheels` Volume) and point the domain wheel at
   `../dist/finance_etl-*.whl` — one `../` because `resources/` sits at the repo
   root (it is `../../../dist/…` only in the template repo, where resources live
   under `projects/<catalog>/resources/`). Serverless does **not** honor
   `--editable`.
2. Copy the job resource the same way → `finance_etl.job.yml` (the scheduled
   refresh); point `pipeline_task.pipeline_id` at
   `${resources.pipelines.finance_etl.id}`.
3. Declare any new variables (e.g. `finance_landing_path`) in
   `variables/medallion.yml`, give them per-target values in `targets/<env>.yml`,
   and pass them through the pipeline's `configuration:` mapping. They do **not**
   go in `databricks.yml` — that file is a thin manifest (bundle name +
   `artifacts:` + `include:` + `sync:`).
4. Make sure the domain package builds. In an adopter repo the root
   `pyproject.toml` IS the domain package — add the new folder to
   `[tool.hatch.build.targets.wheel] packages`, or (cleaner for a genuinely
   second domain) stand up a separate adopter repo per
   [NEW_ADOPTER.md](NEW_ADOPTER.md). Only the multi-domain template repo uses
   `[tool.uv.workspace]` members; adding that block to an adopter breaks
   `make lock`. Then `make install`. The repo-level wiring (framework pin, wheel
   publish, UC bootstrap) is in [ADOPTING.md](ADOPTING.md).

```bash
make validate            # databricks bundle validate -t dev
```

## 7. Bootstrap UC once, then deploy and run

Account-level persona groups must exist first, or every UC grant fails
`PRINCIPAL_DOES_NOT_EXIST` — [NEW_ADOPTER.md](NEW_ADOPTER.md) step 5.
`PROFILE=` pins the workspace; without it the SDK silently uses your DEFAULT
CLI profile, which may be a different workspace entirely.

```bash
make bootstrap-uc TARGET=dev                                       # dry-run: prints the SQL
make bootstrap-uc TARGET=dev WAREHOUSE_ID=… PROFILE=<cli-profile>  # applies it (once per target)
make deploy                                                        # deploy to dev ([dev <you>] prefixed)
make run                                                           # refresh the pipeline
```

Drop a sample file into the landing volume, `make run` again, and check:
silver has the valid rows, `<table>_quarantine` holds the rejects with
`_errors` evidence.

## 8. Edge work is NOT a pipeline

Route with the 3-question router (AGENTS.md "Authoring rules"):
managed medallion table → SDP artifact (always); headless side effects
(exports, API pulls) → python-file task in `src/jobs/<catalog>/` + its job yml;
a human must read the run → notebook task with **no trigger** in
`notebooks/<catalog>/`. Worked examples of both lanes live in the template repo
(`projects/customer_sales/src/jobs/customer_sales/` and
`projects/customer_sales/notebooks/customer_sales/`).
Jobs/notebooks READ pipeline tables, never write them.

## 9. Ship it

```bash
git switch main && git pull
git switch -c feature/finance-domain     # always branch from main
# … commit …
gh pr create --title "Add finance domain" --body-file /tmp/pr-body.md
```

PR template is enforced (`.github/pull_request_template.md`); CI runs the
same `make` gates you ran locally, merge to `main` auto-deploys dev, tags
promote to stage/prod, and the head branch is deleted on merge
([CICD.md](CICD.md), AGENTS.md "Branching & releases").

## When something fails

| Symptom | Where to look |
|---|---|
| `make validate-configs` fails | The error names file + dotted field + fix; field reference in [FRAMEWORK.md](https://github.com/dediggibyte/datalab-framework/blob/v1.0.0/docs/FRAMEWORK.md) |
| Unknown transform/check/snapshot function | Its module isn't in `domain.yml` `imports:`, or the package isn't in pyproject `packages` |
| Stream fails on UPDATE/DELETE from a source table | Add `options: {skipChangeCommits: "true"}` — see FRAMEWORK.md gotchas |
| `Missing pipeline configuration 'datalab.…'` | Add the key to the pipeline resource `configuration:` mapping |
| `ModuleNotFoundError` on Databricks | `pyproject.toml`/source tree didn't ship (`.databricksignore`) or the env cached an old install — full restart |
| Bundle validate/deploy errors | `deploy-databricks-bundle` skill troubleshooting table; [CICD.md](CICD.md) for OIDC |
| Anything SDP the YAML can't express | The capability matrix in [FRAMEWORK.md](https://github.com/dediggibyte/datalab-framework/blob/v1.0.0/docs/FRAMEWORK.md) — extend the framework, don't hand-wire |
